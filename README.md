# 컬러 탈출 · 맵 스튜디오

블록을 같은 색 출구로 밀어내는 퍼즐과 웹 맵 에디터입니다. 게임은 스크롤 없이 한 화면에 표시되며, PC에서 만든 새 맵은 휴대폰이 게임을 열 때 자동으로 받아 저장합니다.

## 실행 주소

- 게임: `https://dadbcdb.github.io/color-block/`
- 맵 에디터: `https://dadbcdb.github.io/color-block/editor.html`
- 기존 오프라인 버전 업데이트: `https://dadbcdb.github.io/color-block/update.html?release=20261108-6`

## PC에서 맵 만들기

1. 맵 이름과 가로·세로 크기(3~14칸)를 정합니다.
2. 바닥과 벽/빈칸을 누르거나 드래그해 그립니다. 비정형 맵과 내부 빈칸도 지원합니다.
3. 색상을 고르고 바닥 가장자리에 입구를 그립니다. 같은 방향·색의 입구를 이어 그리면 넓은 입구로 합쳐집니다. 방향은 자동 또는 직접 선택할 수 있습니다.
4. **역순 제작**으로 넘어갑니다. 이후에는 지형이 고정됩니다.
5. 블록 모양을 6×6 격자에 그리거나 프리셋을 고릅니다. 배치 전에는 90도 회전할 수 있습니다.
6. 같은 색 입구를 선택해 블록을 넣고, 빈 곳으로 이동시킨 다음 다음 블록을 넣습니다. L자 블록은 1칸 입구로 추가할 수 없습니다.
7. **테스트**를 눌러 실제 게임으로 확인합니다. 편집 화면으로 돌아와 계속 수정할 수 있습니다.
8. **GitHub에 저장**하거나 맵 JSON 파일을 저장합니다.

제작 기록을 거꾸로 실행해 모든 블록이 탈출하는지 검사합니다. 블록 제거 시에는 그 블록의 제작 기록도 함께 제거합니다. 벽이나 입구를 다시 편집하려면 블록을 초기화해야 하며, 되돌리기로 복원할 수 있습니다.

작업 중인 맵은 현재 브라우저에 자동 임시 저장됩니다. 새 맵, 복사, 되돌리기/다시 하기, JSON 파일 저장·열기와 저장된 맵 불러오기를 지원합니다. 블록은 연결된 1~36칸, 맵당 최대 64개입니다.

## 에디터에서 GitHub 저장 연결

ChatGPT의 GitHub 연결 정보는 웹 에디터에 전달되지 않습니다. PC의 에디터에서 저장할 때는 `dadbcdb/color-block` 저장소에 대한 **Fine-grained Personal Access Token**을 사용합니다.

- Repository access: `color-block` 저장소만 선택
- Repository permissions: **Contents → Read and write**
- 토큰은 에디터의 비밀번호 입력칸에만 입력하고 채팅이나 맵 파일에 넣지 않습니다.
- 토큰은 현재 탭의 메모리에만 두며 localStorage, 맵 파일, URL에 저장하지 않습니다. 탭을 다시 열면 연결이 필요합니다.
- 저장 대상은 `maps/catalog.json` 한 파일입니다. 다른 맵은 보존하고 변경한 맵만 갱신합니다.
- 다른 PC에서 같은 맵을 수정했다면 덮어쓰지 않고 최신 맵 불러오기 또는 복사를 안내합니다. 목록 자체가 동시에 변경되면 최신 목록에 합쳐 한 번 재시도합니다.

연결하지 않아도 맵을 만들고 테스트하거나 JSON 파일로 저장할 수 있습니다.

## 휴대폰 자동 수신과 오프라인 실행

게임은 공개 GitHub 원본의 맵 목록을 우선 확인하며, 실패하면 같은 사이트의 목록을 확인합니다. 받은 목록은 형식을 검사한 뒤 현재 기기에 저장합니다. 저장소 커밋 후 공개 원본에 반영되면 새 맵을 받을 수 있으며, 웹 배포·캐시 상황에 따라 짧은 지연이 생길 수 있습니다.

게임 실행, 온라인 복귀, 화면 복귀 때 확인하고 켜둔 동안에는 2분마다 확인합니다. 맵 동기화는 플레이 중인 블록·이동 횟수를 초기화하지 않습니다. 새 맵과 수정된 맵은 다음 선택 시 적용됩니다. 인터넷이 없거나 응답이 잘못되면 기존에 저장한 맵과 기본 5개 스테이지를 유지합니다.

아이폰: Safari에서 게임을 열고 **오프라인 준비 완료 → 공유 → 홈 화면에 추가**. 홈 화면에서 처음 실행할 때도 인터넷을 켜고 저장 완료를 확인합니다. 갤럭시도 Chrome의 **홈 화면에 추가/앱 설치**를 사용할 수 있습니다. 웹사이트 데이터를 삭제하면 다시 접속해 저장해야 합니다.

## 개발과 검사

별도 빌드 과정 없이 이 폴더를 GitHub Pages의 main 브랜치, /(root)에서 배포합니다.

```sh
python3 -m http.server 4173
node --test tests/engine.test.cjs tests/map-store.test.cjs tests/offline.test.mjs
```

실제 브라우저 검사에는 Playwright를 사용합니다. GitHub 저장은 테스트용 API 응답으로 검증하며 실제 토큰이나 저장소 쓰기를 요구하지 않습니다.

```sh
npm install --no-save playwright@1.56.1
npx playwright install chromium --only-shell
node tests/mobile-layout.cjs
node tests/editor-sync.cjs
```

브라우저 검사는 6개 화면 크기의 터치 이동·탈출·스크롤 고정·오프라인 재실행을 확인합니다. 에디터 검사는 지형/입구 그리기, L자 배치, 미리보기, GitHub 저장 요청, 충돌 차단, 인증 키 미보관, 휴대폰 동기화 중 현재 판 유지와 오프라인 풀이를 확인합니다. 실제 iPhone/WebView별 동작 확인은 별도로 필요합니다.

## 앱 파일과 맵 데이터 업데이트

앱 코드를 변경하면 `sw.js`의 VERSION과 `update.html`의 EXPECTED를 함께 올립니다. 앱 셸에는 에디터와 공통 엔진도 포함됩니다. `maps/catalog.json`은 앱 셸 캐시에 고정하지 않고 별도로 동기화하므로 **맵을 추가할 때 앱 버전을 올릴 필요가 없습니다**.

맵 형식은 `schemaVersion: 1`이며 바닥 좌표, 색상/방향/길이가 있는 입구, 상대 칸 좌표로 정의한 블록, 검증 가능한 풀이를 포함합니다. 인증 정보와 Android 서명 키는 이 저장소에 포함하지 않습니다.
